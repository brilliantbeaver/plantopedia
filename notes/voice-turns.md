# Continuous Voice Chat — 2026-10-18

This supersedes the earlier recorded-turn interaction. The app now defaults to a persistent, foreground-only voice session using `OPENAI_REALTIME_MODEL=gpt-realtime-2.1`, without WebRTC. Legacy recorded-turn endpoints remain compatible with older clients; the current dock has no Send recording step.

## Interaction

Start Voice Chat once. The glass dock shows connecting, listening/microphone on, hearing, thinking, speaking, or microphone paused. Pause/resume, End, and a speaking-only “Let me speak” control are accessible 44 px targets. Instructions and captions remain disclosures. All seven dictionaries cover the new states. Leaving the screen, backgrounding, signing out, connection loss, or ending closes capture/playback and the session. There is no automatic reconnection or replay of uncertain audio.

Semantic VAD (`eagerness: auto` by default, configurable as low/high) detects completed utterances. The backend owns response creation so it can refresh context and handle interruption ordering. Provider auto-interruption is deliberately disabled: canceling on every speech-start also cancels for brief acknowledgements. Instead, overlapping speech ducks output to 25%; an out-of-band transcript from the same Realtime model distinguishes a narrow set of brief backchannels from meaningful speech. A short “mm-hmm” restores volume and removes the backchannel item without a new answer. Short answers to questions and corrections are preserved. This conservative heuristic is not a universal semantic-intent classifier. A meaningful interruption cancels generation, flushes queued audio, and truncates provider history at the client's actual played duration. The explicit interrupt control is immediate and bypasses classification. Spoken interruptions wait for semantic endpointing/transcription; longer overlapping utterances can remain ducked until their turn ends.

## Streaming and context

`/v1/voice/session` is a WebSocket on the existing API server. The first frame authenticates a Clerk token and selects an owned conversation/locale; tokens never appear in URLs. Origin, frame size, connection counts, ownership, startup timeout, heartbeat, input rate, output/backpressure, 90-second inactivity, 60-second utterance and 10-minute/80-turn session limits are enforced. Server shutdown and owner deletion close sessions. One API process is still required for global owner limits/deletion cleanup.

The server keeps one OpenAI WebSocket, PCM16 mono 24 kHz, the saved voice (`marin` by default), minimal reasoning effort and bounded tool calls. Input streams as captured. Output streams as generated into a bounded application queue. A shared JavaScript pacing adapter releases 100 ms PCM chunks to browser/native playback with about one second of lead, using a monotonic clock. This prevents a fast-generated reply from overflowing the 20-second hardware queue; finish markers wait for queued chunks, and interruption/disposal discard pending audio. There is no WAV completion/download/polling delay. Transcription runs out of band on `gpt-realtime-2.1`, concurrently with normal spoken replies, rather than blocking them. No additional speech model is introduced.

A session seeds the latest 12 valid retained messages, selected plant/photo context or a bounded saved-collection overview. Each user turn refreshes context and validates evidence, including prior ephemeral voice evidence. New text messages added while voice is open are synchronized once, and late transcriptions cannot replace a newer user turn. Recent history uses an ordered bounded database read; duplicate source validations share request-scoped reads. Authorized tools retrieve recent uploads and inspect relevant photos on demand. Read-only calls may run concurrently; proposed changes still require confirmation. Canceled tools cannot start a late reply or leave an unresolved provider function call.

Transcripts honor retention preferences. Completed assistant text is saved only after playback acknowledgment; an interrupted answer is omitted rather than recorded as fully heard. User text is still retained when enabled. Unplayed output is removed from provider conversation context. Source checks run again at persistence; stale/forgotten/deleted evidence fails closed. Audio is streamed in memory, never written to Firebase, app recording files or application telemetry. Provider data handling remains governed by the configured OpenAI account policies.

## Browser and native audio

Web uses an AudioWorklet producing 20 ms frames, continuous resampling from the actual hardware rate, browser echo cancellation/noise suppression, and Web Audio scheduling with a small initial buffer. Playback accounting excludes network gaps. The initial tap primes the audio context before asynchronous new-conversation creation. Muting drops partial capture and disables the track. Late permissions and late packets are fenced after cleanup.

`modules/plantopedia-voice` is a local Expo module, autolinked without WebRTC or another external audio dependency. iOS uses a single AVAudioEngine with voice-processing input and output, mono conversion and timestamped player buffers. Android uses VOICE_COMMUNICATION AudioRecord, available platform AEC/noise suppression, a bounded nonblocking AudioTrack queue and playback-head accounting. Neither records a file. Focus loss/backgrounding stops native audio; speaker routing and audio-session state are released on cleanup.

**Rebuild the EAS development client for native Voice Chat.** Expo Go and existing binaries do not contain this module and show an actionable update message while text remains usable. JavaScript export/autolinking checks do not compile Swift/Kotlin or establish real-device behavior. Physical iOS/Android, Bluetooth/headsets, echo cancellation and interruptions remain acceptance checks. The cloud compilation results below do not establish phone runtime acceptance.

After installing a compatible client, run `npx expo start` and scan the development-client QR code. A configured loopback API is started or reused and checked for readiness automatically; hosted APIs must already be running. Press `w` in that same terminal for web or `s` to select Expo Go for other features. Follow the [README startup and native-install workflow](../README.md#everyday-startup-one-expo-server); changing preview targets does not require another Metro process or a cloud build.

## Reliability and settings follow-up — 2026-10-18

A recoverable tool error previously escaped the live tool handler and closed the entire session. Browser/iOS/Android playback also rejected more than 20 seconds of queued audio, even though Realtime can generate faster than playback; the client’s separate queue for later tool-response items was similarly limited to about 20 seconds. Pacing now prevents hardware overflow while the application buffer remains bounded to the server’s 90-second reply limit plus small headroom. A 45-second synthetic burst test confirms hardware receives only a small lead and interruption/disposal release pending chunks.

Tool failures and malformed arguments now produce a sanitized function result and a spoken explanation, with a 12-second tool deadline and no automatic replay. Authentication/deletion failures still end access. Incomplete responses, unavailable transcripts, empty speech, temporary context-read outages and history-save outages leave the session open with appropriate notices. The app skips an answer when validated context is unavailable and does not claim that an unsaved history entry was retained. Late results cannot resume canceled turns; duplicate played acknowledgments truncate once. Microphone pause restores ducked volume, clears overlapping capture, and rejects late partial commits. Provider cancellation/playback ordering still has a bounded five-second acknowledgment deadline; genuine connection loss and safety limits still end the session.

**Settings → Voice & listening** saves owner-scoped preferences, hydrates existing server settings, coalesces rapid edits in order, reports save failures and supports retry/reset. Existing preference records default safely without a migration. Voices: Marin/Coral/Shimmer and Cedar/Ash/Ballad. Patient/balanced/quick maps to semantic VAD low/auto/high; easy/balanced/less-sensitive interruption varies the brief-acknowledgment window (0.7/1.8/3 seconds). Button only discards overlapping utterances until the explicit interrupt control is used. Headphones use near-field noise reduction; speaker/busy-room use far-field, with the busy-room preset choosing patient turn-taking and less-sensitive interruption. Speaking pace maps to 0.85/1/1.15; calm/expressive delivery is prompt guidance, not a provider “stability” parameter. Voices/settings are fixed for a session and take effect after saving and starting the next chat, matching the provider’s voice-change restriction. Optional synthesized rain/breeze is mixed quietly into outgoing PCM only, disabled by default; it introduces no downloaded recordings, microphone processing or extra provider calls. Advanced settings copy currently uses English fallback under localized headings in non-English locales.

Live verification used synthetic public botanical audio and controlled in-memory context: `gpt-realtime-2.1` completed two spoken turns on one open connection despite a deliberately failed search tool, using Cedar and rain ambience. It did not send private chat/photo data, record microphone audio or write Firebase records. All 337 automated checks pass (65 unit, 31 script, 146 server and 95 component), covering persistence, rapid-edit ordering, retry, old-record defaults, pacing, interruptions, recoverable failures and existing authorization fences. Strict typecheck, lint, API compilation and all-platform export/private-sentinel checks pass. Browser UI inspection in this follow-up was unavailable because computer-use could not access a Chrome window; component tests cover the rendered controls. Physical audio quality, echo behavior and weather-texture listening acceptance remain device checks.

## Contextual spoken acknowledgments — 2026-10-18

Continuous Voice Chat now permits one short, action-specific preamble before noticeably slower lookups or multi-step work, using the same `gpt-realtime-2.1` audio stream. Immediate answers, unclear audio and background sound do not need a waiting phrase. The previous tools-before-speech prohibition was removed; no extra filler response or TTS model was added. Preamble playback does not complete a pending tool turn, interrupted work cannot restart speech, and transcript items have paragraph separation. See [the research, implementation and evaluation notes](voice-preambles.md) for official sources, live evidence and timing/device limits.
