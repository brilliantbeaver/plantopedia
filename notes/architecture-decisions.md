# Architecture decisions and evidence

Revision: configuration follow-up branch `feat/plantopedia-configuration-onboarding`, 2026-10-18. Exact package versions are locked in `package-lock.json`; versions below summarize the chosen compatibility boundary.

- One Expo application, one compiled TypeScript/Express API, shared Zod contracts, Firestore Standard and private Storage. Clerk remains the existing selected application. Mobile has no Firebase Admin or provider clients.
- Local `npx expo start` now manages a missing loopback API through an async [Metro configuration](https://docs.expo.dev/guides/customizing-metro/), requiring service liveness and checking Firebase readiness before the app is served. Dependency failures warn without stopping Expo or killing the API; `/ready` retains its 503 contract with safe failure reasons. Pending SDK checks are shared across polls because the response deadline does not cancel Firebase work. It reuses independent APIs without owning them and uses IPC parent-loss cleanup for its own child. Hosted URLs, CI, exports and production stay independent. `PLANTOPEDIA_AUTO_START_API=false` opts out; use the standalone API watcher when editing backend source. No provider mode, credentials, CORS permissions or database contents change as part of orchestration.
- Node 22.23.1, npm 12.0.2, TypeScript 6.0.3; Expo 57.0.30 / Router 57.0.28, React Native 0.86.3, React 19.2.3. The initial latest template used an RN release candidate and conflicted with Clerk's Expo peer range. Expo 57 was selected instead. The initial implementation locked Expo 57.0.29 / Router 57.0.27; this follow-up records the compatible patch versions already resolved in the pending lockfile. Native cloud-build evidence below belongs to the earlier lockfile, not these patches.
- Clerk Expo 4.11.0, TanStack Query 5.104.3 and SDK-compatible Expo Audio. WebRTC and its config plugin have been removed. Continuous voice uses browser AudioWorklet/Web Audio and an autolinked local Expo duplex-audio module. Native clients require a rebuild; physical-device behavior remains an acceptance gate.
- OpenAI server SDK 7.34.0 and server-only WebSockets use **Realtime**, pinned to `gpt-realtime-2.1`. The latest request supersedes manual recording with foreground streaming, semantic endpointing, conservative backchannel filtering and played-audio truncation. Same-model transcription runs concurrently with ordinary replies. Live synthetic streaming and interruption probes passed; native compilation/device acceptance is pending. See [voice-turns.md](voice-turns.md).
- Firebase Admin 14.5.0; server-only Firestore/Storage. Standard vector indexes must match embedding model/dimensions (1536 initially). Lexical retrieval is bounded and reports limited results; vector quality needs a real-project evaluation.
- `useState`, ordinary functions and explicit dependencies precede additional frameworks. Typed dictionary objects supply translations without a runtime translation framework. Native glass is capability-checked; other platforms use opaque themed surfaces.
- **No local Java/Android/Xcode dependency.** Node tests use injected adapters. EAS CLI 24.8.0 cloud profiles compile native binaries. Actual platform minimums, build images, signing and tested devices remain unverified until the cloud/device proof; this note does not infer them from compilation alone.
- Heroku is the initial public-host recommendation because one persistent process owns finite voice jobs and short-lived audio/status results. Native binaries are distributed through EAS/stores, independently from the API. Multi-instance voice ownership is not implemented.
- npm audit reports transitive advisories in the selected Expo/Metro/tooling graph. Do not apply its suggested major-version downgrades or blanket force fixes. Resolve compatible patches or document reachability before release; a passing test suite does not waive that gate.

Local checks and remaining feature work are tracked in [implementation-status.md](implementation-status.md). Existing notes record the reviewed specification; they are not evidence that the app has passed its live/device release gates.

Cloud verification notes: EAS selected Node 22.23.1 and an Android SDK-57 Ubuntu image; native compilation runs on the hosted worker. At the initial build, Doctor recommended Expo 57.0.30 / Router 57.0.28 while the machine's release-age policy retained 57.0.29 / 57.0.27. The current lockfile now resolves those compatible patches; cloud compilation and physical-device behavior have not been revalidated for the new lockfile. Signed iOS device distribution additionally requires owner-configured Apple signing and export-compliance answers; do not guess those settings. The simulator profile is only a separate compilation check.

Expo CLI workaround: root `postinstall` patches only `@expo/json-file@11.2.1`'s atomic writer to add a random UUID to its content-hashed temporary filename. Concurrent identical signing-cache writes otherwise share a path and can fail on rename. The patch is idempotent and fails on unexpected versions/source; focused tests cover async concurrency, cross-process sync/async writers, restrictive permissions, missing parents and patch guards. It does not require a native toolchain. Reassess/remove the workaround when updating the dependency.
