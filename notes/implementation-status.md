## Adaptive glass navigation and app usability — 2026-10-18

Reviewed the app using the design-critique and accessibility-review skills. The main usability problems were small text-symbol navigation, weak selected states, large repetitive cards, secondary controls competing with primary actions, and failure states that looked empty or disappeared. The implementation now uses a shared Ionicons vocabulary, readable headings, compact photo-led plant cards, consistent page headers, keyboard focus styling, 44–50 px controls and progressively disclosed secondary actions. Explore, collection/search, capture, plant profile, tasks, Ask and settings share these primitives. Capture shows Photo → Details → Identify, preserves the draft warning and keeps optional fields/privacy details collapsible. Profile observations and identification history remain accessible without overwhelming the first view; web/native confirmation dialogs now expose destructive actions deliberately. Tasks distinguish loading, failure and true emptiness. Ask groups history and explanations behind labeled controls, offers starter prompts and starts Voice Chat from an empty conversation. Pending voice-start intent is consumed once and canceled if its screen leaves before recording starts.

Navigation geometry responds to available window width, safe-area insets and font scaling: small phones have 28 px icons and 14 px labels, larger stacked layouts use 29 px icons and 15 px labels, and sufficiently wide layouts place 27 px icons beside 16 px labels. The bar is explicitly centered, grows up to 1040 px and reserves enough height for two-line labels; enlarged text switches horizontal layouts back to stacked layouts when needed. Screen scroll clearance uses the same geometry. Active and inactive states remain readable in light/dark themes. Calculated secondary/nav label contrast on their opaque fallback surfaces is at least 5.8:1. Web glass honors reduced transparency/high contrast, disclosure/voice animation and scroll movement respect reduced motion, and decorative icon glyphs are hidden from the accessibility tree. Assistant emphasis renders without visible Markdown asterisks; original user text is preserved.

Design references: [Apple materials](https://developer.apple.com/design/human-interface-guidelines/materials), [motion](https://developer.apple.com/design/human-interface-guidelines/motion), and [adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass). Chrome inspection verified the wide horizontal bar and a 390 px phone viewport with stacked labels. Geometry regressions cover 320–2560 px, landscape safe areas and doubled text scale. This is focused browser/accessibility verification, not physical-phone acceptance or a full WCAG audit.

Late body errors retain a handler. Callback/multipart paths, credentials, SDK CRC32c validation, retry policies and the default listener threshold of 10 remain unchanged. The patch verifies the exact dependency version and original source hash and refuses unexpected changes; upgrade review must replace or remove it once upstream supplies an independently verified fix.

Ten new Node regressions pass at the default threshold: twelve parallel real-SDK downloads, exact full/range bytes, wrong-checksum rejection, HTTP failure, truncation, upstream closure after cancellation, both response/read orderings, slow-consumer backpressure, late cancellation/error timing and patch guards.
